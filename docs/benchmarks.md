# Benchmarks

Generated by `benchmarks/render_md.py 2026-10-13` from the JSON files in `benchmarks/results/2026-10-13/`. Reproduce with:

```bash
cargo build --release
./target/release/vdb-bench --out /tmp/lowrank --dataset lowrank
./target/release/vdb-bench --out /tmp/mixture --dataset mixture --skip-pq
pip install faiss-cpu numpy && python3 benchmarks/faiss_baseline.py /tmp/lowrank   # and /tmp/mixture
```

**Environment.** Single machine: a cloud container with 4 vCPUs (Intel Xeon @ 2.80 GHz), no GPU. Distance kernel: `avx2+fma`. Other processes were idle during the runs, but this is a shared virtual machine, so expect run-to-run variance of roughly ±10 %. Numbers are from one run each. They are **not** comparable to published numbers from other hardware.

**Setup.** n = 100,000 vectors × 128 dims, 1,000 queries from the same distribution (held out), L2, HNSW M = 16, efConstruction = 200, k = 10. Recall@10 is measured against exact brute-force search (top-100 ground truth written to `groundtruth.ivecs`; FAISS is scored against the same file). The WAL runs with `SyncMode::Never` (no fsync per insert). Latencies are per request through `Collection::search`, which includes validation, query normalisation and building the result objects.

**Datasets** (deterministic, seed 7):

* `lowrank` (default): a 64-component Gaussian mixture in a 16-d latent space, mapped to 128 dims by a fixed random linear map, plus noise. It has low intrinsic dimensionality, like real embeddings.
* `mixture`: a 64-component Gaussian mixture directly in 128 dims. Its high intrinsic dimension makes it a hard case for graph indexes.

## Reading the results

* On both datasets, the from-scratch HNSW reaches the same recall as FAISS `IndexHNSWFlat` at the same M, efConstruction and efSearch. Its recall is equal or slightly higher (+0.00 to +0.04), and its single-query throughput is 0.63–1.05× FAISS's (median ≈ 0.7×). FAISS's batched 2-thread numbers are an upper bound that this engine's request-at-a-time API does not try to match.
* The build is about 1.3–1.4× slower than FAISS's single-threaded build, and each insert here also encodes and appends a WAL record.
* Filtered search keeps full recall at every selectivity. At 10 % selectivity, though, HNSW with `ef / selectivity` explores much of the graph and costs over 10 ms, which is slower than a brute-force scan. The 1 % exact fallback costs about as much again, because metadata is evaluated per slot through a `BTreeMap`. Both are documented limitations; a columnar metadata index and a cost-based planner are the obvious next steps.
* PQ compresses the vectors 15× and reaches recall@10 ≥ 0.95 with rerank ≥ 4. Its QPS here is low because the ADC scan is scalar and is not combined with a coarse quantizer (IVF).
* The earlier, unpublished run in which the `mixture` set reached only 0.73 recall at ef = 256 had a harness bug: queries came from different cluster centres than the base set. That bug is fixed; the queries now come from the same draw as the base set.
